# Deferred Work

The single repository-local home for unresolved follow-ups and possible future sessions. If an external issue tracker owns an item, keep its details there; do not mirror its backlog here.

Entries are planning input, not implementation authorization. Keep each item concise: the problem or outcome, relevant location, and any known constraint or verification need. Do not create `sessions/future/` or hide future work in architecture, commands, workflow files, or archived briefs.

When the maintainer selects work, check it against current code and specifications and prepare one bounded brief in `.agents/sessions/ACTIVE.md`. A planning request authorizes planning only. Active work details belong in that brief; do not maintain a duplicate plan here.

On session completion or context refresh, remove resolved or invalid entries, merge duplicates, update stale assumptions, and consolidate scattered follow-ups. Preserve unresolved intent before removing its old location. If priorities conflict, ask rather than choosing implicitly.

No deferred work is recorded.
